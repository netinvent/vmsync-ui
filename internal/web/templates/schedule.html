How a schedule reaches a host

Saving here changes nothing on a hypervisor directly. Each agent long-polls this UI and picks the change up within seconds, then caches it on disk — so it keeps running the last schedule it received even while this console is unreachable.

Removing an entry stops the timer, but does not stop replication in any stronger sense: anything else invoking vmsync for that VM still works. To make a VM genuinely refuse to be overwritten, set its replication role instead (vmsync -update-role=paused), which vmsync enforces itself and which survives this UI being unreachable.
